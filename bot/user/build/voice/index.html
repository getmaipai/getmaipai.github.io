Ears and voice

This is the stage where the robot stops being silent. It hears its name, works out what you said, thinks about it, and answers through a speaker. Everything in that sentence runs on the Pi in your house. Nothing is sent anywhere.

It is also the easiest stage in the build: no soldering, no breadboard, no level shifter. Two cables and two commands.

What you need for this page

Parts

  • The Pi, set up per Prepare the Pi
  • A 4-mic USB array with echo cancelling and direction finding (XVF3800 class)
  • A small powered speaker with a 3.5 mm input
  • A USB charger for the speaker, and its cable

Software

  • The robot software on the Pi from Prepare the Pi
  • libportaudio2 from apt (this page installs it)
  • About 1 GB free for the voice models

An hour, most of it waiting for downloads.

Why the speaker plugs into the microphone

The speaker does not plug into the Pi. It plugs into the line-out on the mic array, and the array connects to the Pi over USB.

That is not a workaround, it is the whole design:

  • Echo cancelling needs to hear itself. The array removes the robot’s own voice from what its microphones pick up, which is what lets you interrupt it mid-sentence. It can only do that if the sound it is playing passes through it. Plug the speaker in somewhere else and the robot talks over itself and then hears itself as speech.
  • The Pi 5 has no headphone jack. Raspberry Pi removed it. The array’s line-out is the analog output on this robot.

Wire it

  1. Plug the array into the Pi

    Use one of the black USB 2 ports, directly. Not a hub, and not the blue USB 3 port your boot drive is in.

    Never behind a hub

    The array streams isochronous audio, which needs guaranteed bandwidth on the bus. A hub shares that, and the result is dropouts and glitches that look exactly like software bugs. This one is in the hardware record as a rule, not a preference.

    The array may ship with a strip of header pins and a matching socket in a little bag. Those are for its expansion pads, for people running it over I2S or tapping its GPIO. This build does not use them. Nothing gets soldered to this board.

  2. Plug the speaker into the array

    WireFromTo
    3.5 mm audiomic array line-outspeaker input
    USB powera wall chargerspeaker

    Power the speaker from a wall charger, not the Pi. An audio amplifier on the same 5 V rail as the Pi puts hum and hiss into everything it plays, and the Pi’s power budget is already carrying an AI accelerator and a drive.

    You’ll know it worked when lsusb on the Pi lists the array.

Install the voice software

Two parts: a system audio library, then the Python packages.

sounddevice, which everything here records and plays through, is a wrapper around PortAudio, and Pi OS Lite does not ship the C library it wraps. Without it both the microphone and the speaker report missing even with the array plugged in and working.

Name both extras. --extra voice on its own removes the hardware libraries the eyes need.

Install the voice models

Four models do the work, and all of them run locally:

ModelJob
openWakeWordnotices the wake phrase and nothing else
Silero VADdecides when you started and stopped talking
Moonshineturns speech into text
Piperturns text into the robot’s voice

They live in /opt/maipai-bot/models. Take ownership of that directory first, so this install and every future update run without root:

Every file is pinned to a URL and a sha256 hash, and checked after it lands. A file that does not match is refused rather than used. The download is a few hundred megabytes.

What is running where

Worth knowing, because it is the reason this robot behaves differently from a smart speaker:

  • The wake word runs continuously, and it is the only thing that does. It is a small model that recognises one phrase. Audio before the wake phrase is never transcribed and never stored.
  • Speech to text runs only after the wake phrase, on the Pi.
  • The language model runs on the Pi, with the AI accelerator taking it over as that stage lands.
  • Nothing in this chain makes a network request. The only downloads are the model files you just installed.
